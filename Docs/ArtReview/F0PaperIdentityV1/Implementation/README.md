# F0 네 방향 종이 공간 — Unity 구현

2026-09-27. 적용 씬: `Assets/Scenes/InGame.unity`.

상위 폴더의 네 방향 AI 아트 시안을 기준으로 실제 F0를 다시 모델링하고 재질·조명을 적용했다. 이 폴더의 PNG는 **Unity Play에서 실제 PaperCamera로 렌더한 화면**이다. 시안의 투시와 장식 수를 그대로 복제한 이미지는 아니며, 기존 플레이어 크기·카메라·빛 반사 위치·다리 크기에 맞춘 구현이다.

## 실제 화면

| 화면 | 기준 |
|---|---|
| [정면](01-front.png) | 북쪽 0°, 다리와 출구, 천장 광원·덮개·은박 |
| [좌측](02-left.png) | 서쪽 270°, 단서 작업대, 책 기둥, 격자창 |
| [우측](03-right.png) | 동쪽 90°, 종이 더미와 서가, 광로의 측면 |
| [후면](04-rear.png) | 남쪽 180°, 닫힌 제본 벽과 시작 공간 |
| [작업대](05-workbench.png) | 단서 책·메모·깃펜·반응하는 책 |
| [바닥 근접](06-floor-material.png) | 장지 섬유·얕은 굴곡·적층·실·잎 인쇄 |

네 방향은 F0 로컬 좌표 (0, 3.06, -6), pitch -2° 기준이다. 다리를 내리고 일부 광로를 연결한 동일한 테스트 진행 상태다. 새 Play의 최초 상태는 다리가 올라가 있고 2D 도입 컷씬이 먼저 나온다. 정령·카메라는 실제 게임 컴포넌트를 사용한다. 1920×1080으로 저장하며 색상 구분 보조 표식은 테스트 설정에 따라 보일 수 있다. 퍼즐 검증 중 스토리 감독만 일시 정지했으므로 네 방향 캡처에는 동행 새가 나오지 않는다. 스토리 및 동행은 별도 Play 검증으로 확인했다.

## 구현 범위

- 아이보리 장지 바닥: 얕은 접힘, 거친 가장자리, 두께가 보이는 속지 단면, 봉제선, 낡은 적갈색 잎 인쇄. 연속 바닥 충돌체를 유지해 종이 이음새가 추락 구멍이 되지 않는다.
- 사방의 제본 외피와 천장: 종이 벽감, 깊은 서가, 격자창, 접힌 처마, 천장 보. 후면은 가로 제본 띠를 연속으로 이어 실제 북쪽 출구와 구분한다. 문 위·벽 아래·통로 전환부까지 외피를 잇는다.
- 큰 책등 6개와 둥근 기둥 4개: 방 안으로 향한 무광 적갈색 책등, 둥근 띠, 잎 압인, 낮은 광택의 황동 장식.
- 공간 소품: 종이 더미·큰 책상·낮은 종이 아치·꼬인 면실 밧줄·종이 등. 이동 통로와 실제 퍼즐의 광로는 유지한다.
- 움직이는 장치: 기존 다리 힌지에 적층 종이와 실·걸쇠를 부착하고, 여섯 조작부에 고리·종이표·받침대를 추가했다. 은박의 테두리를 보강하되 실제 반사 평면과 판정은 유지한다. 조작 연결 실은 천장을 따라가도록 정리했다.
- 선택적 상호작용: 제본사 기록의 임시 큐브를 종이 메모로 교체했다. 세 반응 책·먼지 털기·펄럭이는 페이지는 공간에 맞춰 위치와 외형을 다듬었다.
- 조명: 서쪽 따뜻한 격자 창빛과 그림자, 동쪽 약한 푸른 보조광, 종이 반사광, 등불, 기존 빛줄기·먼지 연출. F0 전용 볼륨에 ACES, 약한 블룸, 노출·채도를 적용했다.

## 재질과 생성 코드

섬유 원본은 `Assets/_BookTower/Textures/F0PaperIdentity/MulberryFiber.png`이다. 원본 크기는 1254×1254이며 Unity가 같은 소스의 별도 사본을 노멀맵으로 변환한다. Mirror 래핑·밉맵·이방성 필터를 사용한다. 프롬프트와 제작 근거는 [MATERIAL_PROMPT.md](../MATERIAL_PROMPT.md)에 있다.

F0 전용 재질·저장 메시·색보정 프로필은 `Assets/_BookTower/Generated/F0PaperIdentity/`에 있다. 다른 방의 공용 재질을 일괄 수정하지 않는다.

- `F0PaperIdentityMaterials.cs`: 장지·염색 종이·면실·황동·은박 재질.
- `F0PaperIdentityBuilder.cs`: 13개 공간 구역, 모델 생성·저장·배치 결합.
- `F0PaperIdentityMechanisms.cs`: 움직이는 장치·선택적 소품·조명.
- `F0PaperIdentityVerifier.cs`: 구조·재로드 검사와 실제 카메라 캡처.

InGame을 열고 **Book Tower → F0 네 방향 종이 공간 적용**으로 재생성할 수 있다. 현재 F0의 접는 다리 및 빛 퍼즐이 존재해야 하며, 실행 직전 씬 사본은 `Logs/F0PaperIdentityBackups/`에 저장된다. 이전 기본 F0 생성기를 실행하면 이 패스도 다시 적용해야 한다. 메뉴 재실행 시 이 패스가 만든 아트와 메시만 교체한다.

## 검증과 한계

- [구조 검사](structure-check.txt): 13개 구역, 6개 조작부, 원래의 반사판·수광부, 저장 메시·재질·발광, 입구 바닥 135개 지점, 벽과 천장 충돌체 확인. 씬을 저장하고 다시 불러온 Play에서도 검사했다.
- [F0 Play 검사](f0-play-check.txt): 실제 F/마우스 조작, 틀린 광로와 장식 꽃, 다리 점유 중 접기 금지, 양쪽 추락 복귀, 광로 완성, 출구 확인, 문 개방 및 다리→경사로→문→1A 이동 통과.
- [스토리 Play 검사](story-play-check.txt): 2D 도입·대사 전체 표시/다음 대사·키 변경·일시정지·입력 잠금·기억 기록·F0 완료→1A 진행 확인.

별도 검증 프로젝트에서 테스트해 열려 있는 원본 Unity 에디터와 충돌하지 않도록 했다. 검증된 씬·신규 에셋을 원본 프로젝트에 반영했다. 씬 해시 일치, 관련 파일 332개의 일치, 신규 씬 참조 GUID 159개의 존재 및 중복 없음을 확인했다. [최종 반영 검사](integration-check.json)에 기록했다. 열려 있던 원본 InGame 씬은 디스크 변경을 다시 불러와 확인한다.

새 정적 아트는 공간 구역별로 결합해 **84개 렌더러, 1,080,688 삼각형**이다. 기존 캐릭터·소품·움직이는 기믹은 이 수치에서 제외된다. 실제 출시 빌드 GPU 프레임 시간과 저사양 기기 성능은 아직 측정하지 않았다. 자동 검증은 기능 회귀를 확인하며, 초행 플레이어의 단서 이해도는 사용자 플레이 테스트가 필요하다.

배치 실행 중 기존 Unity SearchDatabase 인덱싱 예외와 PaperUISkin의 Sprite geometry 경고가 기록되었다. 이번 아트 C# 컴파일 및 F0 Play 검사 41개, 스토리 Play 검사 43개는 통과했다. Unity가 저장한 YAML의 빈 값 뒤 공백은 유지했다.
