# F0 문 뒤 천장과 1A 입구 정리

2026-10-02. 사용자 스크린샷의 F0 → 1A 통로를 대상으로 한 국소 수정이다.

## 원인과 수정

F0의 높은 출구 문과 낮은 회랑 사이에는 충돌용 천장이 있었지만 실제 화면을 덮는 표면이 이어지지 않았다. 문 회전 공간 위에 두께 있는 장지 천장을 잇고, 높이 차의 옆면과 꺾이는 모서리도 덮었다. 기존 종이 재질을 사용하며 문이 열리는 공간은 유지했다.

1A 남서쪽 입구에 장식용 벽감 선반과 잎 부조가 잘못 배치되어 있었다. 이 입구의 결합 메시에서만 해당 면을 제거하고, 겹장 아치는 유지했다. 통로 끝에서 공중에 떠 보이는 안내 잎·줄기와 입구 바닥 잎도 제거했다. 방 안쪽의 안내와 벽 장식은 유지했다.

추가로 에디터 미리보기 천장의 이름 검사 오류 때문에 같은 프리팹이 중복 생성되던 문제를 고쳤다. 에셋 임포트 때 사용자의 씬을 자동 저장하지 않으며, 기존 중복 천장만 정리한다.

## 검증

- [수정 전](Before/door-sky-0.png), [천장 수정 후](After/door-sky-0.png), [입구 수정 후](After/station-0.90.png).
- [검사 보고서](After/inspection.txt): 문 뒤 4개 위치 × 4방향의 상향 화면 16장에 외부 배경 픽셀 0개. 충돌 레이만으로 완료 처리하지 않고 렌더 화면을 검사했다.
- 꺾인 통로 중심선을 따라 좌·중앙·우측에서 실제 CharacterController 왕복 6회 통과. 벽을 가로지르는 직선 검사 경로는 실제 이동 경로에 맞게 고쳤다.
- [문 연출·통로 검사](foyer-transition-play-check.txt), [F0→1A 이동 검사](traversal-checks.txt), [1A→1B 이동 검사](reading-entrance-checks.txt) 통과. 장식만 제거한 마지막 수정에서는 새 통로 검사를 다시 실행했다.
- 씬의 기존 MonoBehaviour 직렬화 블록이 바뀌지 않았음을 비교했다. 퍼즐 판정과 스토리 연결을 재생성하지 않았다.

자동 검사 시점 밖의 모든 카메라 위치에 대해 수학적으로 틈이 없다고 보증하는 것은 아니다. 이번에 보고된 문 뒤·도착 입구와 기존 두 연결 통로를 검사했다. 새 성능 빌드는 수행하지 않았다.

재적용은 `FoyerPassageOpeningRepair.Apply`이며, 현재 InGame 씬의 해당 천장 루트와 입구만 수정한다. 기존 방 전체를 만드는 빌더는 실행하지 않는다.
