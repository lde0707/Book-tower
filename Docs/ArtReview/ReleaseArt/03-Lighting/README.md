# 완성 아트 03 — 세 방 조명과 검증 범위

2026-10-02. 대상: F0 제본 현관, 1A 그림자 극장, 1B 열람실과 두 연결 통로. Unity 6000.3.10f1 / URP 17.3. 이전 두 단계에서 1B를 같은 범위로 재검증하지 않았던 점을 바로잡아 이번 단계에 포함했다.

## 적용

| 방 | 주광 / 환경광 설정 전→후 | 변경 목적 |
|---|---|---|
| F0 | 0.15→0.08 / 0.67→0.48 | 창빛을 남기고 시작 대지·책등·후면을 모두 밝히던 보조광 감소 |
| 1A | 0.30→0.12 / 0.62→0.43 | 동물 그림자와 스크린의 대비 확보, 입구에는 별도의 방향성 보조광 |
| 1B | 0.12→0.06 / 0.36→0.30 | 서가의 어두운 면과 기억등·독서 공간의 따뜻한 밝기 분리 |

이 값은 프로젝트의 Room/LightingDirector 설정이며 물리 단위 조도 측정값이 아니다. 세 방의 기본 설정 노출은 기존 `PaperSettingsRuntime`의 **postExposure +0.35**를 유지했다. 기존 전역 톤매핑·대비·색보정 프로필도 유지했다.

F0의 시작 보조광 115→55, 후면 130→55, 문쪽 150→80으로 조정했다. 왼쪽 창의 Spot 185→155와 오른쪽 48→30을 사용하며 창빛 그림자 bias를 낮췄다. 1A 장식등은 기존 세기의 56%로 줄이고 장식 Point의 그림자를 껐다. 입구의 새 Spot은 무대 작업면과 거리를 두었다. 1B 정적 종이등은 기존의 62%, 독서 Spot은 80%로 조정했다. 상세 값은 [전](Before/lights.csv) / [후](After/lights.csv), [변경 계약](apply.txt)에 있다.

퍼즐의 실제 반사면, 다리·문·오림 위치, 충돌체와 룸 판정은 바꾸지 않았다. 1A 투사기 선택·강도와 1B 기억등/창문/기록의 상태별 광원 제어는 기존 퍼즐 코드가 계속 담당한다.

## 1B 재질 보완

1B의 공통 장지 `Ivory_Atlas`는 균열처럼 크게 읽히는 색 무늬와 최소 주변광이 고정된 전용 셰이더를 사용했다. 이 공통 바탕을 2번의 URP/Lit 장지 재질로 연결했다. **까마귀 깃발·초상화·문양·창문 인쇄 아틀라스는 유지**했다. 기존의 섬유 장지·책표지·금속 재질도 같은 분류 규칙으로 조정했다.

이 확장 검사 범위의 렌더러 2,576개, 슬롯 2,699개를 기록했다. 슬롯 수는 그대로이며 원본 재질 41개에서 크기별 65개 변형을 사용한다. 범위에는 1B 소속 연결부와 공통 캐릭터도 포함되어 있어 방 본실만의 개수는 아니다. [적용 검사](1B-Materials/apply.txt), [전 재질](1B-Materials/Before/materials.csv), [후 재질](1B-Materials/After/materials.csv).

`ReadingMemoryLantern.prefab`과 `ReadingLanternDock.prefab`도 갱신해 런타임 생성 등불과 받침에 적용한다. 새 모델이나 애니메이션을 제작한 작업은 아니다.

## 실내 반사

조사 시 Lightmap 0, Light Probe 0, Reflection Probe 0이었다. 세 방 각각에 **256px HDR Reflection Probe**를 추가해 금속이 바깥 하늘색 대신 실내의 색과 밝기를 반사하도록 했다. Box Projection과 방 크기에 맞춘 영향 범위를 사용한다. 반사는 정적 캡처이며 움직이는 물체를 실시간으로 비추는 거울 기능은 아니다.

캡처에서 캐릭터·선 광선·입자, F0 다리 장치의 하위 렌더러, 1A 오림, 1B 기억등·문·셔터·기록 패널을 제외했다. 실제 방 구조의 간접광을 굽는 GI 작업은 하지 않았다. 도구는 Unity의 [BakeReflectionProbe API](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Lightmapping.BakeReflectionProbe.html)를 사용한다.

세 프로브의 파일은 `Assets/_BookTower/Generated/ReleaseLighting/`에 있다. 문 뒤의 방이 보이지 않는 정적 반사이므로 모든 관찰각에서 광학적으로 정확한 반사를 보증하지 않는다.

1B 저장 외피는 바닥 396, 천장 396, 측벽 168, 상단 앞뒤 벽 136개 표본, 총 **1,096개 충돌 광선 검사**를 통과했다. 활성 렌더러 2,016개에 누락 재질이 없었다. 의도된 문 입구는 상단 외피 검사에서 제외하며, 입구는 별도 통로 검사로 확인한다. [구조 로그](Checks/structure.txt).

1B 동작 검사에서는 실제 F로 충전·기록 받침 배치·손잡이 회수, 실제 마우스로 걸쇠 조작을 확인했다. 나머지 분기는 거리·가시성 검사를 포함한 기존 상호작용 API로 진행했다. 사람이 처음 플레이하며 이해도를 평가한 테스트는 아니다. [1B 퍼즐](Checks/1b-puzzle.txt), [연결 통로](Checks/1a-1b-passage.txt), [1A 퍼즐](Checks/1a-puzzle.txt), [F0 퍼즐](Checks/f0-puzzle.txt), [F0 문 연출](Checks/f0-door.txt).

F0 시작 기준 활성 그림자 라이트는 전후 4개, 1A 무대는 5→3개, 1B 입구는 3개다. 이는 씬 전체의 enabled+intensity>0 집계로, 카메라에 영향을 주는 수나 드로 콜은 아니다. 인접 통로 라이트가 다수 활성화되어 있어 총 라이트 수만으로 성능을 합격 처리하지 않는다. CPU/GPU 프레임 시간, 목표 기기 성능, 정적 GI·Light Probe는 후속 과제로 남긴다.

## 한계와 후속 작업

- 세 방의 공통 검증 범위를 맞췄지만 검사 지점 밖의 작은 틈·겹침·극단적인 카메라 각도를 전수 검사하지 않았다.
- 벽 인쇄·모서리와 일부 얇은 겹침의 강한 그림자는 주요 소품 단계에서 보완할 부분이다. 특히 1B 창가 문양 면은 주변 장지보다 색 대비가 강하다.
- 정령의 얼굴은 모자 그늘에 들어간다. 해당 비교 화면에서 눈은 식별되지만, 얼굴 안감과 접촉 음영의 최종 가독성은 아직 승인하지 않았다.
- 이번에 적용한 것은 조명 기반과 재질 일관성이다. 레퍼런스와 동일한 완성 그래픽이나 60fps를 달성했다는 뜻은 아니다.
- 검증은 Unity Editor Play에서 수행한다. 이번 단계의 새 독립 실행 파일 빌드나 수동 플레이 결과는 없다.
- 검증 프로젝트 시작 시 UnityEditor.Search 인덱싱에서 `ArgumentOutOfRangeException`이 남았다. 게임 코드 컴파일과 Play 검사는 완료했지만 에디터 로그 전체가 오류 0인 것은 아니다.

## 실제 프로젝트 반영

검증한 씬·생성 재질·반사 맵·프리팹·에디터 도구를 실제 프로젝트에 반영했다. 검사 대상 468개 파일의 SHA-256이 검증본과 일치하며 이 중 89개가 이번 복사에서 추가/변경되었다. 기존 파일 백업은 `Logs/ReleaseLightingMainBackup-20261002-004648/`에 있다. [파일별 해시](applied-sha256.txt), [반영 기록](promotion.txt).

통로 12시점은 `Checks/PassageViews/`에 보존했다. [통로 천장과 벽 예시](Checks/PassageViews/seam-1-0.png), [F0 문 개방 카메라](Checks/door-reveal.png). 표본 수와 촬영 수는 검증 범위를 설명하는 수치이며 모든 위치가 무결함이라는 뜻은 아니다.

## 도구

`ReleaseLightingBuilder`는 기존 광원 원값을 기록하고 세 방 조명·반사를 적용한다. `ReleaseLightingReview`는 목록·노출·품질별 화면을 기록한다. `ReleaseReadingStructureCheck`는 저장된 1B 외피를 검사한다. 적용은 검증 프로젝트에서 진행한 뒤 검증한 에셋·씬·프리팹만 실제 프로젝트로 복사한다. 기존 전체 방 생성기를 다시 실행하면 이번 수정이 덮일 수 있다.
