# 출입구 틈과 방 사이 연결 다리 수정

## 원인과 변경

- `RampGate`가 Awake에서 다리 방향을 덮어쓰고 있었다. 생성 시 방향을 기준 회전으로 보관하고 여기에 접힘 회전을 합성한다. 열린 상태도 원래 다리 경사를 따른다.
- 문 폭을 표본점으로 계산하면서 여유 폭이 과도하게 남았다. 이제 진입판을 포함한 통로 다각형을 벽 두께로 잘라 출입구 폭을 계산한다.
- 대각선 문을 사각형으로 자르면 모서리의 삼각형 벽 부분까지 없어진다. 방 외곽 띠에서 실제 다리 통로만 빼고 남은 부분을 종이 마감 메시와 동일한 충돌체로 생성한다. 일반 외곽 틈도 함께 막는다.
- 14개 다리 양 끝에 방 바닥과 겹치는 평평한 종이 진입판을 추가했다. 모서리 접속에서 다리 가장자리가 바닥 밖으로 먼저 나오는 구간까지 지지한다. 다리 본체도 양 끝에 작은 겹침을 둔다.
- 다리와 진입판의 측면에 연속된 접힌 종이 측벽을 추가했다. 마감과 측벽 높이는 2.4m로 기본 점프 높이 1.2m보다 높다.
- 다리 중간에서는 연결된 두 방을 함께 표시해 목적지 쪽 다리 끝이 허공에 떠 보이지 않게 했다. 다른 방들은 계속 숨긴다.
- 카메라를 돌렸다 되돌릴 때 그림자를 만들지 않는 벽이 계속 숨겨져 있던 `RoomWall` 표시 복구도 수정했다.

## 검증

[연결 다리 14개 플레이 화면](Connections/index.html)

- Python 레벨 검사: 오류 0건, 기존 경고 9건. 장거리 경사로·조감 겹침·2F 판독벽 문 구간·1B 천창 비율 경고는 이번 수정의 통과 여부와 별개다.
- Unity Play Mode: 잠금 문 11개의 방향 확인, 각 문 중앙·안쪽 양끝·바깥 양옆의 5개 접근 경로에서 우회 차단 확인.
- 실제 CharacterController로 다리 14개와 양 끝 진입판을 정방향·역방향 총 28회 통과. 통과 중 기준 바닥보다 떨어지거나 이동이 막히면 실패한다.
- 다리 중간에서 출발·도착 방이 모두 보이는지 검사하고 실제 카메라 이미지를 저장한다.
- 기존 1A/P3/P15 검증도 재실행해 새 구조물이 그림자 경로와 퍼즐 진행을 깨뜨리지 않는지 확인한다.

최종 실행 상태는 [연결부 검증 결과](Connections/play-verification.txt)와 [퍼즐 회귀 검증 결과](Direction/play-verification.txt)를 따른다. 연결부 검증에서는 문을 직접 열어 이동만 분리 검사하므로, 전체 게임 완주나 모든 점프·활공 조합을 검사했다는 뜻은 아니다.

## 재생성

`python Tools/level_layout.py build` 후 `PrototypeSceneBuilder.Build`를 실행한다. 문 마감과 다리 접합부는 씬을 재생성해도 유지된다.

연결부 테스트: `BookTower.EditorTools.DoorwayPlayVerifier.Run`을 Unity batchmode에서 실행한다. 이 메서드는 Play Mode 종료까지 관리하므로 `-quit`은 붙이지 않는다.
