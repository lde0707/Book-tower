# 09 · 룸 시스템

## 왜 필요했나

시작하자마자 플레이어가 화면에 보이지 않는 문제가 있었다.

맵이 나선형으로 감아 올라가는 탑이라 방들이 수직으로 포개진다.
플레이어는 F0(0, **0**, 0)에서 시작하는데, 바로 위 (0, **31**, 0)에
3A 가 51x45 크기로 덮개처럼 얹혀 있다. 직교 카메라를 30도로 내려다보게
두면 위층이 카메라와 플레이어 사이를 그대로 가로막는다.

```
y=36  +--3C--+
y=31  +---3A---+   <- 51 x 45 통짜 슬래브
y=22  |   2D   |
y=10  |   1E   |
y= 0  +--F0--+     <- 플레이어가 이 밑에 깔린다
```

경사, 겹침, 도달성은 전부 검증하고 있었지만 **시야선은 검사 항목에 없었다.**
"오류 0건"이 나왔던 이유가 그것이다.

## 해결 방식 세 가지

### 1. 룸 컬링 - 지금 있는 방만 그린다

`Room` 이 자기 아래 렌더러를 전부 들고 있다가, 활성 방이 아니면 끈다.
콜라이더는 그대로 두므로 물리는 계속 동작하고, 경사로를 오르는 도중에
발밑이 사라지는 일은 없다.

한 번에 방 하나만 그리므로 위층이 가릴 수가 없다. 구조적으로 불가능해진다.

### 2. 면 컬링 - 카메라를 향한 벽을 숨긴다

2E, 3A 는 사방 벽과 천장으로 완전히 닫힌 방이다. 카메라를 어디에 두든
카메라 쪽 벽이 방 안을 가리고, 천장은 항상 가린다.
심즈나 모뉴먼트 밸리와 같은 방식으로 카메라를 향한 면만 숨긴다.

| 카메라 각도 | 카메라 위치 | 숨기는 벽 |
|---|---|---|
| yaw 0 | -z | 남쪽 |
| yaw 1 | -x | 서쪽 |
| yaw 2 | +z | 북쪽 |
| yaw 3 | +x | 동쪽 |
| 전부 | - | 천장 |

**숨긴다 = 렌더러를 끄는 게 아니라 `ShadowsOnly` 로 바꾼다.**
이 게임은 그림자가 곧 정답이다. 벽을 렌더링에서 완전히 빼면 그 벽이
막고 있던 빛까지 통과해서 퍼즐의 정답 자체가 바뀐다.
눈에는 안 보이되 빛은 그대로 막아야 한다.

어느 면인지는 이름이 아니라 형태로 판정한다(`infer_face`).
이름 규칙에 기대면 나중에 이름 하나 바꾸는 순간 조용히 깨진다.
단, "방을 60% 이상 가로지르는 것"만 외벽으로 본다.
이 조건이 없으면 2D 의 기록 4장(0.2 x 3 x 3)처럼 벽에 걸린 퍼즐
오브젝트까지 벽으로 오인해서 숨겨버린다.

### 3. 방 확대 - XZ 를 1.6배

원래 가장 작은 방은 14x12 였다. 이동 속도 4유닛/초 기준으로 3.5초면
가로지른다. 방이 아니라 발판이다.

XZ 평면만 균일하게 키웠다. y 는 건드리지 않았으므로 경사로는 같은 높이를
더 긴 거리로 오르게 되어 오히려 완만해졌다(최대 76도 -> 15도).
구역 위치, 크기, 오브젝트 위치, 크기를 같은 배율로 곱하면 "겹치지 않는다,
도달 가능하다" 같은 성질이 그대로 보존되므로, 손으로 적은 300줄짜리
좌표를 다시 검토할 필요가 없다.

이동 속도는 4 -> 5.5 로 올렸다.

## 지금 어느 방인가 - 판정 순서

```
1) 경사로를 밟고 있는가        -> 그 경사로의 fromId / toId 중 하나
2) 방 부피 안에 있는가          -> 후보가 여럿이면 바닥 높이가 가장 가까운 방
3) 둘 다 아니다 (낙하 중 등)    -> 방을 바꾸지 않는다
```

**경사로를 먼저 보는 이유.** 방의 부피는 위층까지 닿을 만큼 높다.
순서를 반대로 하면 2C->2D 경사로를 오르는 도중에 아래층 1E 의 부피에
들어가 버린다. 1E 바닥은 10, 경사로 높이는 22 로 12나 차이 나는데도 잡혔다.
경사로를 밟고 있다는 건 훨씬 확실한 신호다.

**경사로에 fromId/toId 를 적어두는 이유.** "가장 가까운 방"으로 추측하면
나선 구조에서 엉뚱한 층이 잡힌다. 부피가 큰 옆 층 방이 목적지보다 더
가까울 수 있기 때문이다. 어느 방과 어느 방을 잇는지는 설계 시점에 이미
알고 있으므로 그대로 적어 둔다.

**트리거 볼륨을 쓰지 않는 이유.** 볼륨을 하나라도 잘못 놓으면 그 방에서
화면이 안 바뀌는 버그가 조용히 생긴다. 계산으로 판정하면 그럴 일이 없다.

## 카메라

`PaperCamera.CameraMode.Room` 이 기본 플레이 모드다.

- 방이 한 화면에 들어오면 -> 방 중앙 고정, 방 전체가 보인다
- 방이 너무 크면 -> 플레이어를 따라가되 시선이 방 밖으로 나가지 않게 묶는다
  (`maxRoomOrthoSize`, 기본 20)
- 첫 방은 보간 없이 즉시 맞춘다. 안 그러면 시작 직후 카메라가 엉뚱한 데서
  날아오는 것처럼 보인다
- Tab 을 누르면 전체 조망. 이때는 모든 방을 다시 켜고 천장과 앞벽을 걷는다

## 검증

레벨 파이썬(`Tools/level_layout.py validate`)에 두 가지 검사를 추가했다.

| 검사 | 내용 |
|---|---|
| 구역 간 시야 | 카메라와 방 사이에 다른 방이 끼는가 (룸 컬링으로 실사용에선 해소되지만, 엔딩 조망 연출에서는 문제가 되므로 경고로 남긴다) |
| 구역 안 시야 | 방 안의 벽이 퍼즐 요소를 가리는가. 면 컬링으로 숨겨질 벽은 제외한다. **이건 컬링으로도 못 막는다 - 같은 방이라 항상 같이 그려진다** |

겹침 판정 기준도 높이차 4 -> 9 로 올렸다. 4 로는 "물리적으로 안 부딪힘"만
보장될 뿐이고, XZ 가 겹치는 두 방이 8 정도 차이로 포개지면 어느 방에
있는지 판정이 흔들린다.

`Tools/room_sim.py` 는 `RoomManager.Pick` 을 파이썬으로 옮긴 것이다.
유니티를 켜지 않고 경로 전체를 걸어보며 방 전환을 확인한다.
**C# 쪽 판정 규칙을 바꾸면 이 파일도 같이 바꿔야 한다.**

현재 결과

```
전환 순서 : F0 1A 1B 1C 1D 1E 2A 2B 2C 2D 2E 2F 3A 3B 3C
총 전환   : 15회 / 기대 15회        OK
누락      : 없음                    OK
오판정    : 없음                    OK
서 있을 수 있는 높이 5만 지점 전수 검사 : 오판정 0건
```
