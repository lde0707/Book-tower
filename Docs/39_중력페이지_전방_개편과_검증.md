## 하나의 중심 규칙

중력 페이지의 화살표가 **표시된 기록 운반실의 아래쪽**을 정한다. 가이드에 끼워진 기록 상자들이 함께 움직여 벽과 선반에 멈춘다. 사람과 운반실 밖의 물건에는 적용되지 않는다. 상자와 같은 문양의 빈 자리가 목적지다. 모든 상자가 동시에 제자리에 있어야 해결된다. 먼저 도착한 상자도 다음 방향을 고르면 다시 움직인다.

받침이나 쐐기를 끼워 해법을 유지하는 규칙은 없다. 큰 기록이 좁은 길을 통과하지 못하는 것은 실제 충돌 크기 때문이다. 질량이 커서 더 빨리 떨어지는 규칙도 없다. 이동 중 방향 바꾸기로 순발력을 요구하지 않는다. 상자가 멈추면 다음 방향을 선택한다. 이동 중에도 되돌리기와 초기화는 가능하다.

## 다섯 패턴과 배치

- **천장을 길로 쓰기:** F0, 3C. 직접 가로막힌 길의 위쪽을 이용한다. 도입과 마지막의 짧은 재해석이다.
- **연속 우회:** 1A, 2A. 선반 끝을 차례로 이용해 길을 연결한다. 다음 정지 위치를 먼저 읽는다.
- **함께 움직이는 기록:** 1B, 1D, 2E. 두 상자에 같은 명령이 적용된다. 한 상자의 도착이 다른 상자의 이동을 끝내지는 않는다.
- **크기로 갈리는 길:** 1C, 2B, 2D. 한 칸 기록과 두 칸 기록이 같은 공간에서 다른 경로를 쓴다.
- **세 기록의 귀환:** 1E, 2C, 2F, 3A, 3B, HD. 두 크기와 세 화물의 이동 순서를 함께 계획한다. HD는 선택 방이다.

배치는 `Assets/_BookTower/Design/GravityLayouts.json`에 있다. `Tools/gravity_layouts.py`가 격자 모델의 도달 가능성과 최단 방향 전환 수를 BFS로 확인한다. 본편 배치는 3~11회, HD는 12회의 대표 최단 경로를 가진다. 이는 추론 난도나 재미를 측정한 값이 아니다. 실제 Unity 충돌 검사는 별도로 한다.

## 실제 구현

`GravityPagePuzzle`은 기존 `PuzzleBase`의 활성화, 완료 이벤트, 힌트, 진행 기록에 연결된다. 조작은 기존 F 키와 좌클릭 경로를 그대로 사용한다. 거리와 방 가시성, 게임 진행 상태를 확인한다. 방향 4개와 되돌리기·초기화 2개가 한 페이지에 있다. 방향 표시와 상자 문양은 색만으로 정보를 전달하지 않는다.

화물은 Unity Rigidbody와 실제 BoxCollider로 움직인다. 선택한 축의 가이드가 다른 축 이동과 회전을 막고, 모든 화물에 같은 가속도가 적용된다. 접촉 후 미세한 틈을 정리하는 가이드 정렬은 한 칸의 3.5% 이내에서만 허용한다. 목표 위치로 순간 이동시키거나 정해진 버튼 순서만으로 합격시키지 않는다. 완료는 실제 화물과 목적지의 거리를 검사한다. 정지는 접촉 해결기가 남긴 속도 대신 실제 위치 변화를 보고 판단한다.

2026-10-16 벽 접촉 감속 수정: `StructureCollisionFit`이 고정 선반을 둥근 렌더 메시의 삼각형 충돌면으로 교체하면서, 그 면을 따라 움직이는 화물에 불필요한 감속이 생겼다. `GravityPageRailPhysics.Configure`가 시작 시 기존 선반 BoxCollider를 화물 전용 레일로 재사용한다. `GravityCargo` 레이어(8)의 화물만 평평한 레일과 충돌하고, 플레이어는 기존 정밀 MeshCollider를 계속 사용한다. 충돌체별 제외 레이어로 두 역할을 분리하며 전역 충돌 행렬은 바꾸지 않는다. 런타임 충돌 여유 간격은 0.0005로 적용한다. 가속도·해법·정지 판정·되돌리기·방 배치는 변경하지 않는다.

`BookTower.EditorTools.GravityWallMotionReview.Run`은 네 방향 × 세 레일 간격 × 두 상자 크기로 기존 둥근 면의 감속을 재현하고, 수정 후 자유 이동과 같은 가속·정면 벽 정지·반복 초기화를 검사한다. 결과는 `Logs/WallMotion/rail-regression.txt`에 기록한다. 전체 게임 검사는 별도로 16개 퍼즐과 F0·1A·1B 및 두 연결 통로를 포함한다.

이 수정의 검증 결과: 격리 물리 검사 **121 PASS / 0 FAIL**. 기존 둥근 면의 감속은 24/24 조건에서 재현됐고, 수정 후 모든 조건에서 가속도 12로 1초 이동 시 거리 6.12000, 속도 11.99999로 자유 이동 기대값과 일치했다. 정면 벽 통과 방지와 최종 정지 위치도 통과했다. 기존 ContinuousDynamic 충돌 방식을 유지한다. Windows 새 빌드의 자동 플레이는 `Logs/WallMotion/Standalone/checks.txt`에 **383 PASS / 0 FAIL**, 16개 실제 물리 해법·일시정지·이동 중 되돌리기·F0/1A/1B 구조 충돌·두 통로 왕복을 기록했다. 빌드는 오류 0, 기존 경고 8. 기존 씬 파일의 SHA256은 수정 전후 동일하다. 이 결과는 기능 검증이며 별도의 초행 사용성·시각 검토 합격을 뜻하지 않는다.

읽기·이야기·일시정지 또는 숨겨진 방에서는 화물 운동을 멈춘다. 되돌리기는 위치와 이전 중력 방향을 복구한다. 해결 후 문은 기존 완료 이벤트 또는 연결된 열람실 문을 통해 열린다. F0의 운반 페이지는 해결 뒤 왼쪽 경첩을 중심으로 접혀 문 개방 연출의 시야와 중앙 이동 공간을 비운다. 연출 감소 설정에서는 즉시 접힌다. 작업등은 고정되어 같이 회전하지 않는다.

## 방 구조와 보존 범위

현대화된 `Assets/Scenes/InGame.unity` 위에서 부분 개편한다. 오래된 전체 씬 빌더는 실행하지 않는다. 최초 장면은 `Logs/GravityMigration/InGame-before.unity`에 보존한다.

각 방에 운반실, 앞 관찰 구역, 양쪽으로 돌아가는 통로와 접힌 아치를 구성한다. F0의 기존 골에는 고정 제본 바닥을 놓아 이전 접이식 다리의 필요를 없앤다. 기존 다리·광학 장치·그림자 조작·운반등·접이면과 수집식 해법은 현재 플레이에서 제거한다. 호환성과 과거 작업 복구를 위해 이전 코드와 에셋 자체는 삭제하지 않는다.

공통 종이 재질의 셰이더와 결, 주변 가구와 제본 디테일, 정령의 모자와 모아, 문 개방 연출, 이야기와 이름 회복, Q/E 카메라, 설정과 접근성, F0–1A 및 1A–1B 연결 통로는 회귀 대상으로 유지한다. 새 운반로와 겹치는 이전 충돌체는 제거하거나 천장 높이를 조정한다. 공기 효과의 기존 농도와 재질 보정 기준은 유지한다. 변경된 벽·선반에 맞춰 빛줄기 차폐 데이터를 갱신하고 F0·1A·1B의 간접광 프로브를 재베이크했다. 움직이는 기록, 첫 방에서 접히는 운반실, 열람실 문은 고정 간접광 차폐에서 제외했다.

`GravityPageMigration.Apply`는 자신이 만든 방 루트와 에셋을 갱신한다. 반복 실행해 조작대와 화물이 중복되지 않게 한다. 최초 백업 복원 메서드는 이번 전환의 재작업용이며, 이후 사용자 작업을 보존해야 하는 일반 수정에는 `Apply`를 사용한다.

## 검증 기록 읽는 법

`Docs/ArtReview/GravityImplemented`에 실제 카메라 PNG와 검사 로그를 저장한다. `Iteration01` 및 `iteration02-checks.txt`는 실패를 포함한 개발 중간 기록이다. 최종 결과와 혼동하지 않는다.

자동 검사는 실제 물리 해법, 범위 밖 입력 거절, 이동 중 방향 변경 금지, 일시정지, 되돌리기, 문 개방과 통로의 CharacterController 이동을 구분한다. Windows 빌드 성능은 에디터 검사와 별도로 측정한다. 이미지가 생성됐다는 사실만으로 시각 검토나 초행 재미 검증을 완료 처리하지 않는다.

초행 플레이 테스트는 아직 수행하지 않았다. 숙련 퍼즐 플레이어가 규칙을 이해하는 시간, 첫 가설과 실패 이유를 설명할 수 있는지, 힌트 사용 시점, 반복 입력 비율을 실제 플레이로 확인해야 한다.
