# Unity 적용 순서와 통과 기준

## 0. 공통 프리팹

`BP_RoomSocket`, `BP_BridgeSocket`, `BP_SafeZone`, `BP_CameraZone`, `BP_InteractableMarker`, `BP_LightRayAnchor`를 먼저 만든다. 소켓의 +Z가 방 밖을 향하고, 피벗은 바닥 중앙이다. 문과 다리는 소켓에서만 연결한다.

## 1. F0–1B 수직 슬라이스

F0, 1A, 1B를 새 치수로 블록아웃한다. 플레이어 이동, 카메라 회전, 문 닫힘, 다리 양방향 이동을 검증한 뒤에 장식과 종이 재질을 붙인다.

통과 기준:

- 1A에서 HUD 없이 30초 안에 목표를 찾고, 60초 안에 첫 조작 후보를 고른다.
- 1B의 세 안전섬이 모두 체크포인트로 작동하고 낙하 후 기록/장치 상태가 유지된다.
- 닫힌 문 중앙, 좌우 안쪽, 문틀 바깥 두 지점의 총 5개 접근에서 통과되지 않는다.
- 열린 연결 다리를 앞뒤로 한 번씩 건너며 바닥 이탈이나 방 가시성 끊김이 없다.
- 0/90/180/270도 카메라에서 다음 필수 구역이 전부 장식 뒤에 가려지지 않는다.

## 2. 1C–1E 상호작용 계층

반사 광로, 종이 생물, 무게-그림자 조합을 각각 독립 컴포넌트로 구현한다. 방마다 같은 스위치 기반을 외형만 바꿔 쓰지 않는다. 입력은 F/클릭, 역접기는 Shift를 유지한다.

## 3. 2A–2F 기록 계층

기억 재생, 공간 재배치, 기록 분류, 인과 연결을 상태 그래프로 구현한다. 완료 조건은 방별 SVG의 식을 기준으로 하되 실제 변수 이름과 저장 형식은 구현 시 정한다. 오답은 수집 정보를 지우지 않는다.

## 4. 3A–3C 종반부

3A의 12면 왜상부터 카메라 투영으로 역산한다. 정답 yaw0/pitch30, 올바른 접힘, 전부 뷰포트 안, 애니메이션 안정화 후에만 성공한다. 평행 이동은 정렬 조건으로 사용하지 않는다.

3A–3B–3C 논리 광선은 Y=4u의 +Z 축을 예약한다. 3B의 반사 퍼즐 광선과 P15 역광은 별도 시스템이다. 3C 등대의 높은 시각 광선은 P15 논리 광선에 연결되는 연출만 담당한다.

## 5. 미술·사운드

블록아웃 통과 후 섬유 노멀, 얇은 종이 단면, 연필선, 제한된 크레파스 색을 적용한다. 장식은 이동 콜라이더에서 분리한다. 종이 마찰·접힘·완료음은 필수 시각 신호와 함께 제공하며 소리만으로 정답을 전달하지 않는다.

## 자동/수동 검증

- 각 방 모든 고정 상태와 움직임 양 끝 상태에서 coplanar 후보 검사.
- 표면 간격 0.025u 미만은 하나의 메시로 합치거나 깊이 오프셋.
- 움직이는 물체와 고정 지형 사이 최소 0.35u.
- 모든 문 5점 접근 차단, 모든 다리 양방향 통과.
- 낙하 복구, 저장/불러오기, 운반물 복구.
- 3A 왜상 wrong yaw / wrong fold / beacon off 실패, 정답 상태 성공.
- 새 거대 방 기준으로 프레임 예산과 가시성 구역을 다시 측정.
