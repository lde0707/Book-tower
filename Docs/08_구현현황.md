## 2. 시스템 구조

```
Core/       StateMachine · GameEvents · GameFlow · LevelNote
Player/     PlayerInputReader → PlayerController → PlayerStates(4상태)
Camera/     PaperCamera (직교 · 90° 스냅 · Follow/Overview/Fixed/Cinematic)
Fold/       FoldPanel(4단계) · FoldGroup(조합)
Info/       Keepsakes(유품함) · CollectiblePiece
Echo/       EchoCrease(주름) · EchoInteractor
Puzzle/     PuzzleBase → FoldCombination · PieceAssembly · Sequence
            PuzzleDirector (플레이테스트 기록)
Presentation/ ScreenTransition · FloatingPage
```

**FSM을 쓴 곳과 안 쓴 곳**
- 플레이어(Grounded / Airborne / Glide / Respawn) — 상태마다 물리 처리가 실제로 다르므로 FSM
- 게임 페이즈(Boot/Playing/Paused/Cutscene/Ending) — 사실상 입력 차단 플래그라 enum. 클래스로 쪼개면 파일만 늘고 읽기 어려워진다

## 3. 레벨 — 데이터 기반

**단일 원본은 `Tools/level_layout.py`다.** 씬이나 C#의 좌표를 직접 고치면 검증이 무의미해진다.

```bash
python3 Tools/level_layout.py validate   # 경사 · 겹침 · 도달성 · 퍼즐 정합성
python3 Tools/level_layout.py sim        # 이동 시간 시뮬레이션
python3 Tools/level_layout.py build      # Unity용 JSON 생성
```
그 다음 Unity에서 **`Book Tower ▸ InGame 씬 구성하기`**.

### 검증기가 실제로 잡는 것

| 검사 | 내용 |
|---|---|
| 경사 | 경사로 각도 > CharacterController slopeLimit(50°) → 못 올라감 |
| 겹침 | 두 구역이 XZ로 겹치고 높이차 4 미만 |
| 도달성 | F0에서 출발해 모든 구역에 닿는가 (접힘은 가역이라 양방향) |
| 퍼즐 정합성 | 접이면/조각/주름이 실제로 배치돼 있는가, 정답 길이가 맞는가 |
| 레드 헤링 | 가짜 조각이 정답 목록에 들어가 있지 않은가 |
| 마모 순서 | P11의 정답 순서가 마모 순서와 일치하는가 (아니면 단서가 무의미) |
| 3층 일직선 | 3A·3B·3C가 일직선인가 — 아니면 P15 연출이 물리적으로 불가능 |

### 실제로 잡아낸 문제 (이번 작업)

| 문제 | 조치 |
|---|---|

## 결정 기록

### 활공 — 남기되, 방 내부 높이 설계 때 되살린다 (2026-09-10)

`Docs/06` 원칙 1은 **"올라가기 = 접기, 내려가기 = 활공"** 이다.
그런데 방을 1.6배로 키우면서 y 는 그대로 뒀더니 경사로가 전부 완만해졌고
(최대 76° → 23.8°, 한계는 50°), **전 구간을 그냥 걸어서 오르내릴 수 있게 됐다.**
즉 지금 레벨에는 활공이 필요한 지점이 한 곳도 없다.

빼지 않기로 한 이유는 둘이다.

1. 활공은 이동 편의가 아니라 캐릭터 설정이다 — 책갈피새는 리본이라 날 수 없고
   미끄러질 뿐이다. 빼면 새가 걸어다니는 종잇조각이 된다.
2. 지금 16개 방이 전부 평면이라 3D 인데 2D 처럼 놀고 있다. 접이면을 밟고
   오르는 구간이 들어가면 접기 기믹이 퍼즐만이 아니라 이동에도 쓰이게 되고,
   그게 원래 원칙 1 이다.

**따라서 방 내부 레벨을 채울 때(빈 퍼즐 5개를 만들면서) 같이 높이를 넣는다.**
그때까지 활공은 코드에 남아 있되 쓸 일이 거의 없다.

### 점프 — 넣되 활공과 이어 붙이지 못하게 (2026-09-10)

점프만으로는 1B 의 틈(6.4)을 못 넘지만(4.0), 점프 뒤 활공을 이어 붙이면
7.2 까지 나와서 **P3 가 통째로 무의미해진다.**
그래서 `PlayerController.JumpedThisAir` 로 점프 중 활공을 막았다.
`Tools/level_layout.py` 의 점프 검증이 이 전제 아래 계산하므로,
전제를 바꾸면 검증도 같이 바꿔야 한다.

### 조립 퍼즐은 '맞추는 자리'가 있어야 한다 (2026-09-10)

`PieceAssemblyPuzzle` 이 조각을 다 모으는 즉시 완성되고 있었다.
그러면 P1 의 "걸쇠로 가져가 맞춘다", P13 의 "복원대에 올린다" 가 성립하지 않는다.
퍼즐 데이터에 `at` / `assemblyRange` 를 넣어 그 자리까지 가야 완성되게 했다.
검증기가 그 자리가 허공이 아닌지(가까운 설비가 2.5 안에 있는지) 확인한다.

### F 키 상호작용을 추가한다 — 커서는 남긴다 (2026-09-16)

`Docs/04` 는 완전 캐릭터 조작(B안)을 **"접기 같은 정밀 조작이 답답해짐"** 하나로
물렸다. 그게 유일한 반대 근거였는데, 배치가 다 나온 지금 세어 보니
**조건부로만 맞는다.**

| 방 | 접이면 수 | 접이면끼리 최소 거리 |
|---|---|---|
| 1A | 2 | 14.5 |
| 1C | 2 | 37.5 |
| **1E** | 3 | **8.6** |
| **3B** | 3 | **13.6** |
| **HD** | 2 | **12.8** |

접기 사거리가 7 이므로 둘이 동시에 범위에 드는 방은 **16개 중 3개**다.
그리고 그 3개에서조차 진짜 문제는 '키로 고른다'가 아니라
**'무엇이 골렸는지 안 보인다'** 였다.

그래서 이렇게 했다.

- `TargetInteractor` — 손 닿는 것 중 **몸이 향한 쪽 하나**만 고른다.
  점수는 평면 거리인데 등 뒤는 1.8배 멀게 친다. 지금 고른 것에는 12% 가산점을
  줘서(stickiness) 걸을 때 표시가 깜빡이지 않게 했다.
- `Interactable` — 반응을 둘로 나눴다. 범위에 들면 35%, **골리면 100%.**
  전부 똑같이 반응하면 어느 게 눌리는지 모르고, 골린 것만 반응하면
  "여기 만질 게 있다"가 사라진다. 둘 다 필요하다.
- 룸 컬링이 켜진 방의 물체는 후보에서 뺀다. 실제로 세어 보니 한 곳이 걸린다 —
  **`F0`(표지, 첫 방)의 가장자리에서 `1B` 의 `P3_대체용_접이면` 이 6.4 에 있다**
  (접기 사거리 7). 안 막으면 첫 방에서 보이지도 않는 퍼즐을 건드린다.
  커서 쪽 `InteractionRay` 와 같은 규칙을 키 쪽에도 걸었고,
  `level_layout.py` 에 검사 12번을 넣어 이런 자리가 어디인지 계속 드러나게 했다.
- 입력을 `InteractPressed`(F) 와 `PointerPressed`(좌클릭) 로 나눴다.
  한 변수로 두면 F 를 눌렀을 때 마우스가 놓인 자리로 광선이 나간다.

**커서는 안 뺐다.** 마우스는 멀리 있는 걸 즉시 집고, F 는 화면에서 손을 뗄
필요가 없다. 하나만 남겨서 얻을 게 없다. C안(캐릭터 + 커서)은 그대로 유지되고
입력만 하나 늘었다.

덤으로 `Docs/04` 의 조작표가 구현과 어긋나 있던 걸 고쳤다 —
점프가 표에 없었고, 접기가 "좌클릭 **드래그**" 로 적혀 있었다. 둘 다 사실과 달랐다.

### 경사로에서는 카메라가 따라간다 — 방 안에서는 고정 (2026-09-17)

"방과 방 사이를 넘어갈 때 플레이어가 사라졌다가 생긴다."

원인은 컬링이 아니라 **구도**였다. 방 구도는 방 하나를 통째로 담는데,
경사로는 두 방 **사이**에 있어서 그 구도 안에 아예 없다.
그래서 경사로를 걷는 동안 플레이어가 화면 밖으로 나갔다가
다음 방에 도착해야 다시 나타난다.

전 경사로를 훑어서 재 봤다.

| 경사로 | 화면 밖 구간 | 최대 이탈 |
|---|---|---|
| 1A→1B · 1B→1C | 0% | — |
| F0→1A | 4% | 1.03 |
| 1D→1E | 12% | 1.14 |
| 3B→3C | 14% | 1.27 |
| 3A→3B | 19% | 1.24 |
| 1C→1D | 21% | 1.38 |
| 2C→2D | 23% | 1.16 |
| 2F→3A | 32% | 1.28 |
| 2D→2E | 37% | 1.29 |
| 2B→2C | 39% | 1.31 |
| 1E→2A | 45% | 1.48 |
| 2A→2B | 49% | 1.52 |
| **2E→2F** | **59%** | **1.98** |

(이탈 1.0 = 화면 가장자리. 1.98 이면 화면 절반 너비만큼 더 나갔다는 뜻)

**14개 중 12개**가 화면 밖으로 나간다. 안 나가는 둘은 길이가 짧거나
방 구도가 넉넉해서 우연히 걸린 것뿐이다.

#### 고친 방법 — 방 안에서는 고정, 방 밖에서는 따라감

`PaperCamera.SetTransit(bool)` 을 두고 `RoomManager` 가 켜고 끈다.
켜지는 조건은 **"경사로 위 + 지금 방의 부피 밖"** 둘 다다.

조건을 '경사로 위'로만 잡으면 안 된다. `rampReach` 가 4.5 라서
방 안 출입구 근처에서도 켜지고, 퍼즐을 푸는 도중에 구도가 흔들린다.
**퍼즐은 전부 방 안에 있으므로 고정 구도는 조금도 안 건드린다** — 이게 핵심이다.

검증은 두 번 했다.

1. 전 경사로를 0.5% 간격으로 훑어 화면 밖으로 나가는 지점 1092개를 찾고,
   이 조건이 놓치는 것이 **0개**임을 확인
2. 카메라 보간(`roomFollowSpeed` 3.5)과 이동속도(5.5)를 넣고 60fps 로 돌려
   **화면 밖 1229프레임 → 0프레임**, 최대 이탈 0.92 (가장자리 안쪽)

`transitOrthoSize` 는 `Min` 으로 건다. 좁혀지기만 하고 넓어지지는 않으므로
경사로마다 줌인·줌아웃이 반복되지 않는다.

#### 같이 확인했지만 안 고친 것

경사로 전반부에는 목적지 방이 아직 안 보인다(t 0.5 에서 전환).
두 방을 같이 켜 보는 것도 생각했는데, 표본 574개 중 **48개(8%)에서
반대편 방이 카메라를 가린다**. 룸 컬링을 만든 이유가 그것이므로 그대로 뒀다.
배경이 흰 여백이라 "빈 페이지 위를 건너간다"로 읽히는 쪽이 컨셉에도 맞다.
