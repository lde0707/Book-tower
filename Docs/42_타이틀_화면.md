종료 검증에서는 입력 시스템 종료 뒤 Windows 창 메시지 처리 중 네이티브 오류가 간헐적으로 재현됐다. 최초 `-force-d3d11` 비교는 성공했지만 기본 D3D11에서도 후속 재현됐으므로 그래픽 API 단독 원인으로 결론 내리지 않았으며 그래픽 설정 변경은 되돌렸다.

Unity에 함께 설치된 PDB의 심볼과 오류 주소를 대조하면 `PlayerMainWndProc`의 `WM_GETOBJECT / UiaRootObjectId(-25)` 처리 뒤 객체 접근에서 실패한다. 이는 [Windows UI Automation 사용 후 종료 오류 UUM-146676 수정 기록](https://unity.com/releases/editor/whats-new/6000.3.21f1)과 일치하는 경로다. provider 해제만 수행한 첫 보완은 후속 요청을 막지 못해 실패했고, 이를 최종 성공 결과로 세지 않는다.

`WindowsQuitCleanup`은 확정된 `Application.quitting`에서 Windows 전용 `BookTowerWindowsQuit.dll`을 호출한다. 해당 네이티브 모듈은 현재 스레드의 Unity 창에만 종료용 메시지 필터를 설치하고 provider를 해제한다. 종료 중 `WM_GETOBJECT`는 더 이상 Unity의 종료된 객체에 전달하지 않으며 다른 메시지는 원래 처리기로 보낸다. [Microsoft 문서](https://learn.microsoft.com/en-us/windows/win32/winauto/wm-getobject)도 닫히기 시작한 창은 이 요청에 응답하지 않도록 설명한다. [provider 정리 문서](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationcoreapi/nf-uiautomationcoreapi-uiadisconnectallproviders)는 해제 중 provider를 다시 게시하지 않도록 요구한다.

소스와 재빌드·네이티브 메시지 검사는 `Tools/Native/WindowsQuit.cpp`, `WindowsQuitTest.cpp`, `build-windows-quit.ps1`에 있다. x64 MSVC/Windows SDK로 정적 CRT를 링크한다. 콜백 모듈은 프로세스 종료까지 고정해 Mono/플러그인 정리 뒤 메시지도 안전하게 처리한다. 게임 실행 중 접근성, 다른 앱, 엔진 버전·URP·그래픽 API는 유지한다. 실제 반복 종료 결과는 아래 최종 결과에서 구분한다.

## 화면과 조작

- **이야기 시작:** 현재 세션의 첫 이야기로 진입한다. 지속적인 퍼즐 진행 저장 기능이 없으므로 이어하기를 표시하지 않는다. 기존 기록장·설정은 기존 정책대로 유지한다.
- **설정:** 기존 조작·화면·소리·접근성 설정을 연다. 닫기 또는 변경 취소 시 타이틀로 돌아온다. 게임 도중의 설정은 계속 일시정지 메뉴로 돌아온다.
- **나가기:** 종료 확인창을 연다. Esc는 종료 확인, 확인창의 Esc는 취소다. 확인창이 열리면 뒤의 타이틀 버튼은 입력을 받지 않는다.

마우스와 키보드를 지원한다. 위·아래 키로 선택하고 Enter로 실행한다. 선택된 메뉴는 얇은 밑줄, 옅은 종이 띠, 화살표로 표시한다. 타이틀과 설정 화면에서는 게임 시간과 플레이 입력을 정지하고 전용 메뉴 음악을 재생한다. 이야기 시작 시 원래 카메라의 렌더 레이어·배경·클리어 설정을 복원하고 메뉴 음악을 종료한다.

배경은 화면 전체를 덮도록 비율을 유지하며 잘라 표시한다. 메뉴는 기존 1920×1080 UI 기준 프레임 안에 유지한다. 제목에는 기존 프로젝트의 NanumMyeongjo ExtraBold, 메뉴에는 기존 UI 글꼴을 사용한다. 큰 글자 설정을 반영한다.

## 아트 생성과 자산 관리

배경은 내장 **image_gen** 도구로 새로 생성했다. 핵심 프롬프트는 “왼쪽은 제목과 메뉴를 위한 조용한 상아색 종이 여백, 오른쪽은 남색 천제본의 펼친 책에서 접힌 도서관과 아치가 솟고 가는 황금빛이 길을 잇는 16:9 종이 공예 일러스트, 글자와 UI는 제외”다. 전체 영문 프롬프트는 위 GenerationPrompt.txt에 보존한다. 생성 원본을 프로젝트로 복사했고 제목·메뉴는 이미지에 굽지 않고 실제 UI로 표시한다.

텍스처는 mipmap과 CPU 읽기를 끄고 최대 2048, 고품질 압축 설정으로 임포트한다. NPOT 스케일을 None으로 두어 원본 비율을 보존하고 가장자리는 Clamp한다. 대상 플랫폼이 이 크기의 압축을 지원하는지는 실제 빌드 임포터 결과를 따른다. 배경 음악은 기존 `Audio/FantasyLibraryV4/04_MainMenu.wav`를 스트리밍 자산 그대로 참조한다. 큰 음원을 복제하지 않는다. 자산 준비를 반복해도 같은 ScriptableObject를 갱신하며 배경이나 오브젝트를 누적 생성하지 않는다.

## 검사 실행

Unity 에디터 실행 메서드는 `BookTower.EditorTools.TitleScreenReview.Run`, 타이틀을 포함한 Windows 빌드는 `BookTower.EditorTools.TitleScreenReview.Build`다. 빌드에서 `-titleQA`로 타이틀 자동 검사를 실행할 수 있다. 일반 실행은 항상 타이틀에서 시작한다.

`-skipTitle`은 자동화용 직접 게임 진입이다. 기존 `-gravityQA`, `-releaseArtProbe`, 다른 BookTower.EditorTools 검증 진입점도 기존 검사 범위를 유지하기 위해 타이틀을 건너뛴다. 타이틀 검증은 이들 게임플레이 검사와 별도로 실행한다. 검증용 설정과 기록장은 사용자 저장 경로에서 격리한다.

로그와 렌더는 `Logs/TitleScreen/Editor`, `Logs/TitleScreen/Standalone`에 기록한다. 1920×1080, 1280×720, 1280×1024, 2560×1080과 큰 글자 상태를 확인한다. 기능 검사, 렌더 시각 검토, 실제 빌드 검사는 별도 결과로 기록한다. 기존 벽 밀착 감속 문제는 이 타이틀 작업의 해결 범위가 아니다.
