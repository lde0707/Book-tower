# 성능 최적화와 런타임 구조 정리

2026-10-08. Unity 6000.3.10f1 / Windows / Intel Core Ultra 5 225H, Intel Arc 130T.

## 변경 범위

원본 InGame 씬, 배치, 메시, 텍스처, 퍼즐 해법과 콜라이더는 수정하지 않았다. F0·1A·1B의 고정된 아트는 빌드 복사본에서만 정적 배칭한다. 문, 흔들리는 종이, 캐릭터, 상호작용 오브젝트, 중력 퍼즐 전체는 제외한다. 알 수 없는 동작 컴포넌트가 있는 계층도 제외한다.

- `RoomStaticBatching`: Unity 기본 배칭보다 먼저 실행하는 빌드 처리. 실제 배칭 수가 0이거나 중력 퍼즐이 배칭되면 빌드를 실패시킨다. F0 228개, 1A 942개, 1B 1,927개가 빌드 시 배칭됨을 확인했다. 실행 중 비활성 오브젝트 때문에 집계 수는 다를 수 있다.
- `PaperRenderQuality`: 그래픽 프리셋의 단일 소유자. 보통은 100% 해상도·기존 SMAA High를 유지하며 MSAA를 중복 적용하지 않는다. 깊이 선처리를 사용해 뒤에 가려진 면의 비싼 조명 연산을 줄인다. 높음의 4x MSAA·115% 렌더 스케일은 유지한다. 낮음은 75% 해상도·SMAA를 쓴다. 안티앨리어싱 방식이 바뀌므로 모든 픽셀이 이전과 같다는 뜻은 아니다.
- `RoomVisibility`: Room/RoomBound의 공통 가시성 관리. 변화가 있을 때만 순회하고, 숨길 때의 렌더러·광원 상태를 복구한다. 원래 꺼져 있던 광원을 임의로 켜지 않는다. 콜라이더·GameObject 활성 상태에는 관여하지 않는다. 벽의 카메라 방향 갱신도 상태가 달라질 때만 한다.
- `GravityPagePuzzle` / `GravityPagePresentation`: 물리·되돌리기와 완료 연출을 파일 단위로 분리했다. 배열 구성·양수 파라미터를 초기화 시 검증하고, 물리 이전 위치 배열을 재사용한다. 보이지 않는 방의 활성화·힌트 진행을 멈춘다. 완료 연출 후 변환을 계속 쓰지 않는다.
- `BindingDoor`: 콜라이더를 한 번 수집하고 개방 시작 때 한 번 해제한다. 완전히 열린 뒤에는 회전 갱신을 멈춘다. 기존 예고 시간·개방 속도·소리 시점은 유지한다.
- `Interactable`: 숨겨진 방에서 거리 계산·장식 움직임을 멈추고, 반응이 끝난 물체는 같은 위치·광량을 반복해서 쓰지 않는다.
- `PaperSettings`: 메모리 복사와 값 비교를 JSON 입출력에서 분리했다. 키 배열은 독립 복사한다. 모든 공개 설정 필드의 변경 감지를 자동 검사해 새 항목이 비교 함수에서 누락되는 것을 잡는다.
- `PaperHud`: HUD 갱신을 뷰 구성에서 분리하고 대상·키·접근성·동작이 바뀔 때만 안내 문자열을 만든다.
- `PaperAtmosphereDirector`: 방의 프로필 참조를 캐시하고 수렴한 환경광을 매 프레임 재업로드하지 않는다. 안개 셰이더는 기여도가 정확히 0인 가까운 구간만 건너뛴다. 안개 밀도·그림자·광량은 낮추지 않았다.
- Windows 빌드는 LZ4HC로 압축한다. 배칭으로 늘어난 메시 데이터까지 포함해 출력 크기가 617,487,136 → 381,951,919바이트로 감소했다. 설치 출력 크기이며 런타임 RAM 감소율이 아니다.

## 측정 방법과 증거

실제 렌더링하는 Windows 플레이어를 사용했다. `-batchmode` 플레이어는 사용하지 않았다. 1920×1080, 보통, VSync 해제, 프레임 제한 없음, 방별 해법 실행 후 같은 카메라, 3초 준비 후 15초 표본이다. 이동 중 60초 실사용이나 여러 PC의 평균을 뜻하지 않는다. 열·백그라운드 부하에 따른 변동이 있으므로 평균뿐 아니라 p95도 남겼다.

- 최초 상태 전체 회귀와 측정: `ArtReview/Optimization/Before/checks.txt`
- 그림자·공기 효과 분리 측정: `ArtReview/Optimization/Batching/checks.txt` — 이 단계는 배칭 순서 오류를 발견하기 전이므로 실제 배칭 수는 0이다.
- 실제 정적 배칭 적용 측정: `ArtReview/Optimization/Batched/checks.txt`
- AA·깊이 선처리 분리 측정: `ArtReview/Optimization/AntiAliasing/checks.txt`
- 최종 전체 검사·실제 백버퍼 캡처: `ArtReview/Optimization/Verified/`. `Final/`은 DepthNormals 보완 전 중간 단계다.

초기 QA의 고정 1600×900 캡처는 단일 샘플 RenderTexture를 사용하므로 MSAA 간 시각 비교 자료로 쓰지 않는다. `Verified/*-perf-*.png`는 실제 프레임 종료 후 백버퍼를 캡처한다. 4x MSAA와 SMAA/깊이 선처리는 같은 빌드에서 비교한다.

## 최종 기본 설정 측정

- F0: 평균 66.65 → 26.53ms (15.0 → 37.7FPS), p95 71.52 → 27.23ms, 그리기 호출 3,008 → 2,333.
- 1A: 평균 38.41 → 17.93ms (26.0 → 55.8FPS), p95 43.07 → 20.56ms, 그리기 호출 5,821 → 4,844.
- 1B: 평균 57.84 → 23.52ms (17.3 → 42.5FPS), p95 71.18 → 25.90ms, 그리기 호출 8,805 → 5,398.

세 방의 평균 프레임 시간은 최초 측정 대비 약 53~60% 감소했다. 최초 측정 중 편집기 진단도 실행했으므로 머신 부하에 따른 차이가 포함될 수 있다. 같은 수정 완료 빌드에서 MSAA 4x만 복원했을 때도 F0 55.62ms, 1A 33.31ms, 1B 45.89ms로 느려져 AA/깊이 처리의 기여를 따로 확인했다. RAM은 유의미한 감소를 주장하지 않는다. 비개발 빌드에서 GC Allocated In Frame 계측기가 제공되지 않아 GC 총량을 0으로 판정하지 않는다.

## 최종 검증 상태

- Windows 실제 플레이: **351 PASS / 0 FAIL**. 16개 퍼즐 실제 물리 해법, 일시정지·되돌리기·보간 복구, 문 개방, 카메라 회전, 16개 방 구조물 콜라이더와 아치 입구, 가구 접촉, F0–1A 양방향 및 1A–1B 3개 차선 양방향 통로를 검사했다.
- 시각: 실제 1080p 백버퍼에서 F0·1A·1B의 기본/4x MSAA를 비교했다. 중간 단계에서 ReadingPaper 무늬 누락을 발견해 ReadingPaper/CrayonAtlasRepeat에 DepthNormalsOnly 패스를 추가했다. 1B 깃발·바닥 까마귀 무늬와 1A 장식이 복구된 화면을 확인했다. 해당 패스 누락은 이제 빌드 검사 실패다.
- 빌드: 성공, 오류 0. 기존 미사용 필드 등 경고 8개는 남아 있다.
- 메뉴·설정 편집기 검사: 2026-10-11 병합 복구 후 **76 PASS / 0 FAIL** (`ArtReview/PaperUI/play-check.txt`). 키 재지정, 값 변경·취소·저장, 화면 설정 15초 자동 복구, 일시정지 중 효과음, 읽기·기록·종료 취소를 확인했다.
- F0 문 연출·통로: 병합 복구 후 PASS (`ArtReview/Optimization/foyer-transition-check.txt`). 문 개방 중 이동·점프 잠금, 카메라 프레임 안의 문 회전, 개방음, 개방 완료 후 이야기 진행, 입력 복구, F0–1A 덮인 경사 통로의 실제 CharacterController 이동을 확인했다.
- 1A–1B 연결부: 병합 복구 후 PASS (`ArtReview/ReadingEntrance/play-check.txt`). 세 차선×양방향 실제 CharacterController 이동, 12개 카메라 시점에서 외부 배경 노출 0픽셀, 양쪽 방에서 통로 가시성을 확인했다. 이 배경 검사는 구조 틈 검사이며 최종 조명 품질 판정과 구분한다.
- 미검증: 전 구간 장시간 이동 성능, 다른 GPU·해상도, 초행 재미. 내장 GPU에서 모든 방의 60FPS를 보장하지 않는다.

중간 실험 이미지 중 최종 비교에 불필요한 것은 `Logs/Optimization/IntermediateCaptures`로 옮겼다. 원본 로그와 최종 검증 이미지는 Docs에 유지한다.

## 2026-10-11 Git 병합 복구

원격 `631135e3`은 파일 4,951개를 삭제한 커밋이며 추가·수정 파일은 없다. 로컬 `75d4a4b9`의 현대화된 씬·코드·검증 자료와 병합할 때 4,930개가 삭제되고, 로컬에서 수정한 21개가 수정/삭제 충돌이 됐다. 원격의 대량 삭제는 실행 씬·조명·게임 코드까지 포함하므로 현재 게임을 유지하는 방향으로 해결했다.

기존 파일과 Git 인덱스를 `Logs/MergeRecovery/2026-10-11/`에 백업하고, 없어진 파일만 로컬 HEAD에서 복구했다. 기존 21개 작업 파일은 덮어쓰지 않았다. 병합 커밋 `41450d83`의 파일 트리는 직전 로컬 커밋과 동일하며, 미해결 충돌은 0개다. GitHub 푸시는 수행하지 않았다.

추가 UI 검사에서 기존 테스트의 고정값 두 곳을 실제 구현에 맞췄다. 푸터는 이미 56px인데 테스트가 60px을 기대했고, 약 58ms 효과음을 100ms 후에 검사하고 있었다. 효과음은 재생 직후 일시정지 중 재생 여부를 검사한다. 게임의 UI 크기나 소리 길이를 바꿔 테스트를 통과시키지 않는다.

## 재검증

Unity 배치 실행 메서드 `BookTower.EditorTools.GravityPageReview.Build`로 빌드한다. 해당 빌드 후 실행 파일에 `-gravityQA "출력 절대 경로"`를 주면 16개 퍼즐·충돌·양방향 통로와 성능을 검사한다. `-gravityMSAAReference`는 기존 4x MSAA와 비교하고, `-gravityQualityAblation`을 추가하면 같은 빌드에서 MSAA 4/2 및 SMAA+깊이 선처리를 비교한다. `-gravityPerfOnly`는 첫 세 방만 검사하므로 전체 회귀 PASS로 보고하면 안 된다. 일반 실행에서는 QA 프로브가 만들어지지 않는다.

향후 방 제작 시 움직이는 참조를 정적 대상으로 등록하지 않는다. 새 동작 컴포넌트는 기본 제외이며 소유하는 변환을 확인한 뒤 허용한다. 빌드 검사와 실제 플레이어에서 `isPartOfStaticBatch`를 모두 확인한다. 씬 전체 재생성이나 아트·콜라이더 단순화는 이번 최적화에 포함하지 않는다.

## 2026-10-16 플레이 성능과 로컬 용량

`PaperRenderQuality`의 현재 렌더 스케일은 낮음 67%, 보통 80%, 높음 100%다. 보통의 3D 픽셀 수는 기존 100% 대비 36% 감소하며 FSR 1.0과 선명도 0.35를 적용한다. 화면 UI는 표시 해상도를 유지한다. 높음은 기존 115% 초과 해상도 렌더링을 제거하고 4x MSAA는 유지한다. 축소된 3D 영상의 가는 선과 작은 무늬는 원본 해상도와 완전히 같지 않다.

사용하는 게임 셰이더가 읽지 않는 `_CameraOpaqueTexture` 복사를 비활성화한다. 실내 공기 효과는 기존 Full Screen Pass의 자체 `_BlitTexture`를 계속 사용한다. 그림자 거리·광량·퍼즐·모델·충돌은 이번 변경 대상이 아니다. 작업 시작부터 수정돼 있던 `InGame.unity`는 시작 시 SHA-256 `0D8498AAD86DA798F13655EA0426781501D4E62673C32DDB88BC3EE840A42BC2`와 동일하게 보존했다.

`Tools/compress_recovery_backups.ps1`은 지정한 과거 복구 폴더 네 개만 압축한다. ZIP의 모든 파일을 원본과 SHA-256으로 대조한 후 원래 폴더를 제거하며, 재실행 시 이미 처리한 폴더는 건너뛴다. 67개 파일이 737,677,848 → 65,273,715바이트로 줄어 **641.25MiB**를 확보했다. ZIP은 `Logs/*.verified.zip`에 남아 있다. 이는 로컬 백업 절감이며 게임 배포 크기 감소가 아니다. Git은 `repack -a -d --keep-unreachable`로 재정리했고 전체 `fsck` 및 HEAD·브랜치·태그 불변 검사를 통과했다.

Windows 빌드는 382,431,437바이트, 오류 0, 기존 경고 8개로 성공했다. `-gravityNativeReference`를 추가하면 동일 빌드·방·카메라에서 보통 설정과 기존 100%/자동 필터/불투명 화면 복사 설정을 비교한다. 측정 로그에 실제 렌더 스케일도 기록한다. 최초 기존 실행 파일 측정과 전체 기능 검사 중 수치는 다른 작업 부하가 섞여 있으므로 최종 성능 비교 자료와 구분한다.

전체 Windows 플레이 회귀는 **351 PASS / 0 FAIL**이다. 16개 퍼즐 실제 물리 해법·정지·되돌리기, 문·카메라, 구조 충돌, F0–1A 양방향 및 1A–1B 세 차선 양방향, 귀환 통로를 통과했다. 근거는 `Logs/PerformanceMaintenance/Functional/checks.txt`다. 실제 1080p 출력의 F0·1A·1B에서 UI·퍼즐 표식·재질·조명이 출력되는 것을 확인했다. 초행 플레이와 장시간 이동 성능은 별도 검증 대상이다.

최종 비교는 빌드·Git 압축·무결성 검사 종료 후 Intel Core Ultra 5 225H / Intel Arc 130T에서 실시했다. 1920×1080, 보통, VSync·FPS 제한 해제, 각 모드 3초 준비 및 15초 측정이다. 같은 실행 파일의 원본 해상도 → 최적화 설정 결과는 다음과 같다.

- F0: 평균 30.39 → 25.47ms, 약 32.9 → 39.3FPS. p95 31.99 → 26.40ms.
- 1A: 평균 22.08 → 18.87ms, 약 45.3 → 53.0FPS. p95 23.20 → 19.99ms.
- 1B: 평균 26.39 → 21.75ms, 약 37.9 → 46.0FPS. p95 27.33 → 22.62ms.

평균 FPS는 약 17~21% 향상됐다. F0를 포함해 60FPS 고정은 달성하지 못했으며 RAM 감소도 주장하지 않는다. 비교 로그와 실제 백버퍼 이미지는 `Logs/PerformanceMaintenance/Comparison/`에 있다. F0·1A·1B의 원본/최적화 화면을 검토했으며, 원거리 가는 선의 선명도 차이는 있지만 퍼즐 표식·방 구조·재질·조명의 누락은 확인되지 않았다. 낮음 화질의 1B 렌더도 별도로 검토했다. 이 시각 검토는 장시간 이동 중 깜빡임이나 초행 가독성 테스트를 대신하지 않는다.

Unity의 배칭 후처리 순서 0은 [Unity 6000.3 소스](https://github.com/Unity-Technologies/UnityCsReference/blob/6000.3/Editor/Mono/PostprocessScene.cs)에서 확인했다. 정적 배칭이 원본 오브젝트별 컬링을 유지하는 것은 [Unity StaticBatchingUtility 문서](https://docs.unity.com/en-us/engine/6000.3/script-reference/unityengine/staticbatchingutility)를 참고했다.
